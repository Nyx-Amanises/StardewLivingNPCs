# 00 · 重写目标、约束与洁净室纪律

> 本文档是整个说明书包的宪法。**每个参与实现的 AI 对话在开工前必须完整阅读本文档和 01。**

## 1. 背景与目标

LivingNPCs（Yuki 作，Nexus 已发布，UniqueID `Yuki.LivingNPCs`）目前依赖一个修改版的
ValleyTalk（原作 dandm1，LGPL v2.1，UniqueID `dandm1.ValleyTalk`）提供 AI 对话引擎，
两个 mod 以桥接接口协作。本次重写的目标：

1. **合并为一个 mod、一个文件夹、一个 manifest**：对话引擎成为 LivingNPCs 的内部模块。
2. **完全的创作权**：新引擎不得包含上游 dandm1 的任何"表达"（代码、提示词文案、传记
   文本、世界观描述文本）。功能与思路可以相同——版权不保护功能。
3. **对老用户无缝**：已发布的 LivingNPCs 用户升级后，存档数据、API 密钥配置自动迁移，
   游戏体验连续。
4. 移除对 Content Patcher 的强制依赖（默认角色资料由主 mod 自己加载）。

### 非目标

- 不追求与旧版行为逐字节一致（提示词文案是重新创作的，输出必然不同）。
- 不保留对 `dandm1.ValleyTalk` 的 interop API 兼容（`RegisterPromptOverride` 等
  第三方接口按新命名重新设计）。
- 不支持从"原版 ValleyTalk（非本 fork）"迁移数据。

## 2. 洁净室纪律（最重要的一节）

本说明书由读过旧代码的一方（dirty room）撰写，实现方（clean room）**从未且不得
阅读旧 ValleyTalk 源码**。这是新代码不构成衍生作品的核心保障。

### 实现方（每个接手的 AI 对话）必须遵守

1. **禁止打开** `ValleyTalk/`、`ValleyTalk.Tests/`、`upstream-ValleyTalk/` 目录下的
   任何文件。包括"只是看一眼格式"。你需要的全部行为约定都在本说明书里；如果缺了，
   在文档里记录开放问题并停下来问用户，**不要去翻旧代码补齐**。
2. **禁止搜索引擎检索** ValleyTalk 的源码镜像或代码片段。
3. 可以自由阅读：本说明书包、`LivingNPCs/`、`Shared/`、`LivingNPCs.Tests/`、
   搬运清单（03）中列为 MINE 并已复制到新位置的文件、星露谷/SMAPI/Harmony 官方文档
   与源码、Stardew Valley Wiki。
4. 例外：**权属地图（02）中列为 MINE（≤10% 上游行）的文件是 Yuki 的原创**，复制、
   阅读、改写它们都不受洁净室限制——它们会由搬运步骤先行复制进新目录。

### 说明书撰写方已经遵守的规则（供审计）

- 对上游/混合权属的代码只做**功能级**描述：行为、输入输出、格式、约束、边界情况；
  不含代码片段，不逐类翻译原结构。
- 不引用上游提示词、传记、世界观文本的原文；只描述"这段文本需要传达什么"。
- 数据格式、存档键名、资产路径、配置字段名**按原样精确记录**——格式与标识符不受
  版权保护，且是兼容契约所必需。

### 权属依据

`02-ownership-map.md` / `ownership_map.json` 由 `tools/ownership_map.py` 生成：
以上游仓库全部 git 历史的实质代码行为语料，逐文件计算当前代码中上游表达的残留比例。
分类阈值：≥60% UPSTREAM（重写），≤10% MINE（搬运），中间 MIXED（默认重写；
文件级别的甄别结论已写入 03 搬运清单）。该地图 + 本说明书 + 各实现对话的记录
共同构成"独立创作"的证据链，请全部入库保存。

## 3. 硬约束（所有工作包共同遵守）

- **目标框架/依赖**：与现有 LivingNPCs 一致（net6.0 风格的 SMAPI mod 工程、
  Harmony 由 SMAPI 提供、GMCM 可选依赖）。以 `LivingNPCs/LivingNPCs.csproj` 现状为准。
- **命名空间**：新引擎代码一律在 `LivingNPCs.Dialogue.*` 下（见 01）。
- **不得引入新的 NuGet 依赖**，除非工作包文档明确列出。
- **日志前缀、玩家可见文案**走 i18n（见 15），中文为第一语言，英文必备。
- **多人联机**：凡读写存档数据的路径必须考虑"仅主机持久化"的 SMAPI 规则（见 14）。
- **线程模型**：LLM 调用全部异步、不阻塞游戏主线程；回到游戏状态的写操作必须回到
  主线程执行。各工作包文档中标注了并发敏感点。
- 每个工作包完成后必须能**独立编译**且现有 `LivingNPCs.Tests` 全绿。

## 4. 法律立场备忘（给用户，实现方可跳过）

- 上游代码按 LGPL v2.1 发布，作者在 Nexus 页面的"须经我同意"声明约束不了已按
  LGPL 授权的代码；现行 fork 的分发方式本就合法。
- 重写完成后，新 mod 不再含上游表达，LGPL 不再适用，Nexus 页面权限声明也无从
  附着；创作权完整归 Yuki。
- 旧 `ValleyTalk/` 目录在重写验收通过后从仓库删除（保留 git 历史即可，
  历史中的 LGPL 代码带许可证，合法）。
- 建议在发布说明中如实写明"对话引擎为独立重新实现，不含 ValleyTalk 代码"，
  避免 Nexus 争议时被动。
