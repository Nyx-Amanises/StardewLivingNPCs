# 世界之外的本地上下文召回

本页记录世界之外的本地上下文选择。记忆和往日历史召回已在 `48a7822` 完成，基线为 `8bbc9b1`；本轮以 `48a7822` 为基线，继续处理当前连续会话的正文输入预算。世界条目检索保持原实现，本地选择不增加语义路由、embedding、重排或摘要请求。

## 当前连续会话的提示词预算

本轮只为 `PromptAssembler` 的原生 `CurrentConversation` 小节建立预算视图，默认最多 **8,000 个 UTF-16 字符**（`.NET String.Length`）。预算覆盖整个小节，包括角色标签、换行、数据边界及转义结果、标题、介绍和省略提示，不是只计算台词正文，也不是 token 上限。

原生小节能放入预算时，完整保留原有短会话输出。需要选择时，优先当前尚未回答的玩家消息及最近最多四个完整交流轮次（exchange）；在剩余空间中，有限补回与当前问题相关的旧轮次、包含承诺、拒绝、取消或更正的原文证据，以及邻近后继。所选内容最终按原顺序排列，缺口有省略标记，并明确说明这只是有限的原文摘录。

无法容纳的旧轮次按整组跳过，不从半句截断。异常超长的最新玩家消息也不裁成前半段问题，而是提供“当前消息不可用、请缩短后重述”的明确提示，避免把更早的问题冒充本轮输入。正常游戏输入框已有 500 字符上限。第三方 `CurrentConversation` 覆盖内容超过小节预算时，回退到原生预算视图。

选择复用本地词项与原文线索，不调用模型生成摘要。承诺、拒绝、取消和更正的识别属于启发式筛选，不能保证任意旧事实都被保留，也不能仅凭相关性判断某项约定是否仍有效。当前权威关系、状态和有效事项继续在各自上下文中独立提供；有限摘录不能覆盖这些事实或授予动作权限。现有内容过滤和不可信数据边界仍然生效。

完整会话缓存和最终提交保留原文及原有 GUID；持久化仍按原规则保存完整文本、说话者和会话首 GUID，生成取消时的事务边界不变。本地动作、同意和重复施压等规则继续读取原有完整上下文，较早的拒绝不会因正文投影省略而从本地证据中消失。辅助远端请求沿用各自既有窗口：路由最近四条，动作补充最多六条且逐条限长；元数据分类器继续处理本轮玩家输入、已生成正文、选项及行为上下文。这一预算只约束正文请求中的当前会话小节；往日历史仍使用单独的 4,000 字符预算，整包提示词可以超过 8,000 字符。

## 哪些内容检索，哪些直接保留

| 内容 | 处理方式 | 保留边界 |
| --- | --- | --- |
| 长期记忆、玩家偏好 | 原有本轮查询排序上增加双向中英别名 | 预算仍是 3 / 4 条；无匹配沿用原显著度、场景、时效排序 |
| 社区印象 | 同一检索器支持明确人物姓名及话题别名 | 仍最多 2 条，仅当前 NPC 已知、未到期记录；来源和隐私字段不变 |
| 共同经历、已结束求助、已解决冲突 | 从合格记录中查询，每类最多 2 条可选历史 | 有匹配时只补匹配历史；无匹配时取原排序前 2 条；完整存档不删减 |
| 有效行为倾向、未完成求助、未解决冲突 | 固定提供全部合格活跃事项 | 不再受历史 Top 4 限制；已排队但未领取的金币奖励也保留 |
| 本轮应出现的一次性接续提示 | 共享计划固定保留，再与历史摘要去重 | 只标记实际提供的对象；只读关系快照不消费提醒 |
| 往日对话、事件、旁听/目击 | 本轮问题可查询最近 20 条以外的已有记录 | 完整记录、日期和说话者保留，总预算仍为 4,000 字符 |
| 当前连续会话 | 正文使用上述 8,000 字符小节预算；短会话完整保留，长会话选择近期轮次及有限旧证据 | 完整缓存和存档不裁剪；原文摘录不裁决事实有效性或动作授权 |
| 当前关系/状态、动作权限 | 继续直接提供 | 不用相似度裁决婚恋状态或动作授权；有效事项不与会话历史争用预算 |
| 人物传记、亲属和性格 | 继续作为稳定 NPC 前缀 | Penny 中文人物正文约 716 字，单独检索收益小，可能损害角色一致性 |

“可选历史最多 2 条”不包括固定保留事项。活跃事项很多时，提示词会比旧 Top 4 更长；这是避免遗漏有效约束的预期行为。少量历史本来已完整出现的场景，也未必进一步缩短。

## 查询与事实边界

`MemoryTopicQuery` 共用原来的词项计分。104 组受控等义词覆盖部分中英物品、活动、场所及明确人物姓名，例如咖啡/coffee、清静/quiet、人多/crowds、垂钓/angling。没有直接词面重合时才使用较弱的别名辅助分；不会把“钓鱼”扩成“海滩”，也不扩展推断得到的标签。

人物别名要求候选 Subject 是明确身份，不把另一人的文本提及当成该人的记忆。否定、偏好类型、日期、来源和生命周期保持原文/结构化事实；检索分数不是事实更新。16 个固定双语回归样例覆盖已有词面缺口，不是独立语义准确率评测，也不能证明任意换说法均能命中。

历史行为计划在筛选、固定提示和标记之前应用现有 RSV 资格规则，逐条检查求助步骤等字段；被过滤的记录不挤占配额，也不令相邻允许记录被整行删掉。客机继续用主机摘要，没有增加跨 NPC、跨存档的全库检索，也没有把主机记忆库发给客机。

本轮查询仍来自 `CurrentPlayerText`，只存在于本次选择中。开场、送礼或定时触发缺少当前输入时，不把旧问题当作新问题。正常记忆回忆计数沿用原标记路径；`48a7822` 已修复只读主机关系摘要仍会消费一次性接续提示的问题。

## 往日记录的预算

没有有效查询时，保留原来的最近 20 条 / 4,000 字符路径。有查询时先给最近一条可容纳的完整记录留空间，再保留最新匹配和高相关记录，补最近两条作为接续；相关记录最多 6 条，最终按时间正序输出。查询没有答案时只保留最近接续，不制造答案。

最新匹配的保留有助于避免较新的双语更正被多条旧词面命中挤掉；这不是通用的冲突事实判定器。日期和原文仍由模型与当前权威状态共同解释。超出预算的单条会话不会被截成半句；它会被跳过，并继续尝试其他完整记录，修复此前一条过长记录令后续历史全部消失的情况。

检索只使用已过滤的实际台词与事件/说话者字段，不用本地化模板、农夫显示标签中的词作相关性证据。当前会话已独立提供，继续排除在往日记录中。存档原有保留期限和清空机制仍生效，检索不能恢复已经删除的历史。

`48a7822` 还修复了动作合同对求助状态的识别：只读每项请求的顶层状态，不再把已完成/过期请求内部步骤的 `Pending` 误当成进行中的请求。分号连接的多项请求分别判断，未知格式继续使用完整合同回退。

2026-09-12 用 `8bbc9b1` 和后来提交为 `48a7822` 的隔离构建运行真实生产召回、行为上下文与提示词装配器。该批尚未限制当前会话小节。新旧进程读取同一份合成状态；中文提示词使用生产 `MergeLocalizedPrompts`，同场景共用已经检索出的世界条目。固定 Penny / Town / 第 1 年冬 17 日 / 6 心，未加载玩家存档或游戏运行时。数字为 UTF-16 字符数，包含换行，不是 token。

| 场景 | 行为上下文：旧 → 新 | 整包输入：旧 → 新 | 整包变化 |
| --- | ---: | ---: | ---: |
| 无历史积累 | 3,234 → 3,234 | 16,015 → 16,015 | 0% |

往日记录另做模块对照：26 条记录中，目标在 40 天前。无查询时仍为 20 条 / 1,422 字符；有查询时从旧版的 20 条 / 1,422 字符且无目标，变为 3 条 / 308 字符且含目标。加入一条超长最新记录后，旧版输出 0 条；新版无查询为 19 条 / 1,350 字符，有查询为 2 条 / 237 字符且含目标。这里统计各条记录字符之和，存储内容前后哈希一致。整包基准使用相同的独立 HistoryLines，不能把这一模块的节省再加到上表。

## 配置模型的真实请求（48a7822 历史记录）

使用用户授权的现有配置调用 `deepseek-flash`，显式发送 `thinking: {type: enabled}`、`reasoning_effort: low`、`max_tokens: 16000`，流式接收，单次超时 85 秒，不重试。三组成对合成请求共 6 次，顺序为旧→新、新→旧、旧→新。只发仓库资料和合成状态，凭据、服务地址、原始提示词与回复未纳入 Git 记录。

| 场景 | 旧版首段正文 / 主请求完成 | 新版首段正文 / 主请求完成 | 输入 token：旧 → 新 |
| --- | ---: | ---: | ---: |
| 历史较多，普通问候 | 6.408 / 6.762 秒 | 2.874 / 3.423 秒 | 5,795 → 5,595 |
| 追问较早共同经历 | 5.679 / 6.133 秒 | 4.547 / 5.305 秒 | 5,800 → 5,543 |
| 中文查询英文偏好 | 2.661 / 3.153 秒 | 4.333 / 5.030 秒 | 5,800 → 5,611 |

每个场景只有一对样本，缓存命中、推理长度和正文长度不同，不能据此声称稳定提速；偏好场景输入更短却更慢。6 次请求均以 `stop` 正常结束，没有耗尽 16,000 的预算。完成 token 为 375–974，其中推理 token 为 282–874；模型没有因为上限提高就生成到上限。

用实际测量时捕获的 Snapshot 和 ActionContract 调用生产正文/内联元数据解析器：6/6 正文成功且非空、均有 4 个选项，没有可见元数据或思考标签泄漏；严格内联元数据只有 4/6 通过。新旧两条问候均缺少元数据标记，真实游戏会继续走完整分类器，本次没有调用或计时该回退。因此这些数值是主请求耗时，不能当作最终游戏展示耗时，也不能报告为 6 次完整流程通过。6 份合成场景均因缺少运行时能力上下文使用完整动作合同，不是精简合同的实测。未加载游戏画像、实时物品目录或执行任何动作。

回复质量也有边界：旧版对地图集经历表示不记得，新版能提及检索出的图书馆/地图集，但补写了“脆弱纸页、装订处折页、抚平”等记录中没有的细节。这证明召回覆盖得到改善，不能证明回答完全忠于记录。偏好场景新旧回复都接受安静的需要，这一对样本没有显示明确的正文质量提升。后续应单独用事实一致性样例检查补写往事的问题。

完整脱敏数据与哈希见[本地上下文召回基准](benchmarks/context-retrieval-20260912.json)。只含 `48a7822` 该批代码的隔离副本通过完整回归：**2,597 通过、0 失败、1 项原有跳过**；基准请求工具的 9 项 Python 测试通过。构建与测试使用 `-p:EnableModDeploy=false -p:EnableModZip=false`，游戏中的模组 DLL 未变化。这些结果属于当前连续会话预算实现之前。

## 后续架构优先级

当前连续会话的正文预算见上节。后续仍需用更多跨语言改口、指代和长距离约定样例检验旧证据选择，不能把有限摘录视为完整事实库或承诺状态摘要。完整缓存和存档的容量管理属于另一项工作。

台词风格样本已有场景排序和 20 条上限，但缺少字符预算，适合以后做去重及代表性采样。人物传记和亲属关系目前较小，而且有稳定前缀价值，优先级低于会话增长。

向量检索仍需用真实漏召回案例与受控别名做同预算对照。当前规模无需向量数据库；每轮串行请求远端 embedding 会重新引入网络等待。提前显示正文仍按[原评估](early-dialogue-display-assessment.md)处理，当前会话预算未改展示与动作提交时序。

`48a7822` 的测量工具：[measure_memory_context.ps1](../tools/measure_memory_context.ps1)，要求 PowerShell 7.2 或更新版本；该次实际使用 PowerShell 7.6.5 / .NET 10.0.11，加载 Debug / net6.0 生产程序集。它使用两个独立进程运行真实生产选择器、行为上下文和提示词装配器，只用合成状态；真实 API 调用由单独的 [benchmark_dialogue_latency.py](../tools/benchmark_dialogue_latency.py) 执行。DeepSeek 测试夹具可显式提供 `thinking_type: enabled`，保持与生产 Low 档参数一致。
