## 已有证据能说明什么

[离线基准](benchmarks/world-retrieval-20260912.json) 使用真实生产 renderer/index、四种随包资料、固定 Penny / Town / spring。每组暖机 20 次、测量 100 次，共 44 组。生产 DLL 为 Debug / net6.0，在 PowerShell 7.6.5 / .NET 10.0.11 下运行：各组 `Retrieve` 中位数为 0.0564–0.48985 ms，最高 P95 为 0.6473 ms，单次最大 6.3015 ms。

| 世界变体 | 可检索条目数 | 旧 renderer 全文字符 | “图书馆在哪里” core + retrieved | 字符减少 |
|---|---:|---:|---:|---:|
| 原版完整 | 67 | 11714 | 2269 | 80.6% |
| 原版精简 | 61 | 7786 | 1682 | 78.4% |
| SVE 完整 | 95 | 16014 | 2269 | 85.8% |
| SVE 精简 | 89 | 10332 | 1682 | 83.7% |

这是世界模块的 UTF-16 字符数，不是 token，不含外层 prompt wrapper、其他提示词模块或模型时延。全世界查询分别保留 67/67、61/61、95/95、89/89 条，均比旧全文增加 144 字符；这类查询不能靠检索无损缩短。基准也不包括首次资源读取、索引构建或主线程状态捕获，因此不能证明首轮游戏帧耗时已经合格。

现有测试覆盖中文别名/部分话题、中文不同句式共享词、英文名字词界、本轮问题优先、指代续问、完整列举、SVE 四变体、失效后的旧快照、worker 不读取游戏资源、记忆不额外落盘和回忆计数时机。这证明了这些用例的行为，没有证明无词面重合的语义召回率，也没有 embedding 对照组。

## 数据域优先级

| 数据域 | 当前规模与特点 | 向量检索的潜在价值 | 建议 |
|---|---|---|---|
| 当前 NPC 的长期记忆、玩家偏好 | 分别最多 24 条；自由文本、个人经历多 | 换说法、含蓄表达、中文问题对应英文记忆 | 第一试验对象；先限单机/主机已有合法候选 |
| 世界条目 | 完整版 67 / 95 条；已有中英实体和话题别名 | 新内容包缺少别名、描述性问题的长尾覆盖 | 保持词项默认；有明确漏召回数据后再试 |
| 社区印象 | 当前 NPC 最多 16 条；带来源、可见性、期限 | 转述文本的释义匹配 | 后置，收益要抵得过知情边界和误召回成本 |
| 人格、当前关系/场景、行动合同、进行中的约束 | 对当轮回答有确定性约束 | 相似度不能证明事实、权限或动作可执行 | 固定事实/规则继续直接提供，不交给向量筛选 |

记忆检索目前用 `LocalTextSearch` 的词项与中文双字片段；它没有世界侧 `WorldEntryAliases.QueryTerms` 的中英话题扩展。例如“人多吵得我紧张，想清静一点”与英文记忆“prefers quiet evenings and avoids crowds”可能没有查询词重合。这是值得测试的语义缺口，不能直接当成向量模型已能正确命中的证据。

向量也容易把“以前喜欢咖啡”和“现在不再喜欢咖啡”判为相近，或混淆 Penny/Pam、玩家本人/别人转述。否定、主体、时间、事实状态和知情权限必须由结构化字段及明确文本约束处理；相似度只提供候选。

## 本地与远端

优先评估可选的小型多语本地 embedding，要求中文和英文位于兼容空间、支持目标 Windows / net6 环境中的 CPU 推理，并实际检查量化后的准确率。模型版本、tokenizer、query/document 前缀、池化与归一化策略都要固定。当前没有证据足以选定具体模型或承诺速度。

本地的优势是无需每轮网络往返，个人记忆不必另发服务端；代价是模型包体、加载内存、CPU 竞争、原生运行库维护和冷启动。远端可减少本机模型负担，但每个新问题仍要编码，文档向量缓存不能消除这次往返，容易重新引入类似旧语义路由的等待。远端应是明确选择的独立选项，不能因为配置了聊天 API 就自动上传整个记忆库；世界公开资料与个人记忆的可发送范围要分别定义。

文档和查询必须使用兼容的同一向量空间。不能用某个远端模型预编码文档，再用另一个本地模型编码问题后直接比较。

目前无需向量数据库或近似近邻服务。示例采用 384 维 float32 时，95 条世界向量约 143 KiB，单 NPC 64 条记忆/偏好/印象约 96 KiB，不含模型、文本和元数据；顺序点积搜索足够简单。主要新增成本在编码模型和每轮 query 编码，不能把“向量比较很快”当作端到端方案很快。

## 混合选择与提示词边界

1. 先按当前存档、权威来源、NPC 知情范围、SVE 开关、过期/遗忘及现有 RSV 规则确定合法候选，再做任何排名。结束时再次核对请求版本，不能先搜跨域全库再尝试隐藏结果。
2. 保留精确实体、当前事实和必要场景的确定性保留规则。完整世界/完整分类列举继续走现有完整选择；“你好”、空输入等不需要强行寻找相似记忆。
3. 对有足够信息、词项覆盖不足的查询，取词项与向量候选并集。可先试基于名次的融合（如 RRF），避免把余弦分数直接加到现有显著度/IDF 分数上。明确本轮实体优先，旧场景只是次要线索。
4. 对向量候选设置经标注集校准的接纳条件，允许没有合适结果。不能无条件拿“最近的几个”，也不能为不同模型统一拍一个余弦阈值。偏好反转、旧承诺、近期重复回忆等继续服从原事实状态和生命周期规则。
5. 保持现有预算进行对照：长期记忆 3 条、偏好 4 条、社区印象 2 条；世界软预算 8 条/6000 字符，确定性保留和全量查询沿用现有例外。长世界描述可以分片检索，但最终按 entry ID 合并并输出完整条目，避免半段事实失去上下文。

稳定 core、人格与行为规则不进入向量候选的增删范围；检索结果仍作为带来源的数据进入动态尾部。记忆/资料中的文字不因被检出而获得指令优先级。“那里怎么走”继续利用有限紧邻前文和确定性指代逻辑；当前已有明确新主题时，不把长旧对话拼进 embedding 淹没本轮问题。无需额外 LLM 改写/重排调用。

## 缓存、更新与失败回退

| 对象 | 缓存与更新边界 |
|---|---|
| 世界文档向量 | 键包含语料域、条目 ID、完整/精简、SVE、语言、内容指纹及完整编码配置；复用 `worldRevision` 的失效/快照语义。新请求只使用已发布完整版本，旧请求保留自己的不可变快照。 |
| 个人记忆向量 | 派生缓存按存档/权威拥有者/NPC/事实键与内容指纹隔离。新增或 summary/subject 等编码内容变化才重编码；信任、回忆计数等排名元数据变化无需重编码，但每次排名必须读当前快照。 |
| 遗忘、到期与清空 | 同时撤销检索资格和派生缓存；迟到的后台结果检查事实版本与 session generation，不能把已删记忆重新放回索引。向量缓存不是权威存档。 |
| Query 向量 | 只在会话内做小容量缓存；键包含实际编码文本、必要的指代上下文和编码配置。原始查询不写入长期记忆/持久化检索日志；换存档、退出标题或主机切换时清空。 |

固定主线程职责为捕获合格事实、文本和版本，以及原有提交/计数操作。资源读取和本地化渲染仍通过现有游戏线程 capture 冻结文本；模型加载、embedding tokenizer 初始化、编码、向量索引构建和网络全部在有界后台任务中，后台不读取活的 NPC/Game1 或内容管线。当前 `BehaviorMemory.BuildPromptContext` 仍在生成请求时完成状态规范化和回忆标记，不能直接改成跨线程访问同一 `LivingNpcState`；应先建立纯数据快照，再把筛选结果交回既有权威路径，不重复触发 `MarkRecalled`。

建议试验预算：主线程不得同步等待编码；捕获成本以目标机器 P95 < 1 ms 为待验证目标。冷模型未就绪立即用词项路径；热模型新增等待先设 100 ms 硬期限并测量，超过期限直接采用本轮原词项结果。100 ms 是可调整的验收上限，不是已有实测性能。编码 worker 先限制为 1 个，按内容指纹合并重复任务；无法中途取消的 native 推理也不能堆积重试，迟到结果不得改写已装配提示词。

模型缺失、加载失败、维度/版本不兼容、缓存损坏、超时、断网或请求失效，都回到同一快照的现有词项检索；保留其 core、预算、确定性保留与完整查询行为。不要用更宽的数据域或其他 NPC 的缓存补结果。诊断只需模型/索引版本、命中路径、候选数和耗时，默认不记录原始私密文本。

## 联机需要单独设计

`ValleyTalkContextService.ResolveBasePromptContext` 在客机权威模式下只使用主机的 `BehaviorContextSummary`，缺失时返回空；不会因本轮输入而调用客机自己的记忆召回。`NpcRelationshipViewMessage` 同时携带克隆的 `BookState` 供已有只读用途，但这不是把所有书册记录升级成跨 NPC 对话检索语料的理由。当前视图按 NPC 共享，也不能假定已有逐玩家私密记忆隔离。

第一版试验可保持单机/主机检索，客机沿用既有摘要。若以后要支持客机本轮语义召回，需要明确的主机查询协议：校验发送者、NPC、会话/存档版本及允许的资料范围，在主机筛选，只返回该次查询允许使用的摘要与必要来源字段。不要把主机全量文本或向量库同步到客机；查询超时/断线仍用已有权威视图，不回退客机本地心智。

社区 `Private` 信息可能属于当前 NPC 已知内容，但 `CommunityPropagationRules.CanRetell` 禁止其继续传播。语义相关不能将其改成可公开转述，不能去掉 `Source`/`Visibility`/`HeardFromNpcName`/期限，也不能将猜测升级为目击事实。远端编码是否可发送某段文本是另一条边界，不由“玩家和 NPC 有关联”自动成立。

## 下一步怎样决定是否实施

先建立人工标注的小型离线评估集，覆盖：精确实体对照、无词面重合的中文换言、中英双向查询、混合语言/别称、否定与偏好反转、不同主体/旧事实、无答案、指代与换题、不同存档/NPC/客机、隐私和到期清空。分别比较当前词项、增加受控别名、纯向量、混合；用独立保留的问法调参和验收，不用模型自己宣布命中正确。

在相同上下文预算下，记录分数据域/语言的 Recall@k、Precision@k、无答案误召回率和错误实体率，同时记录首轮/热态编码、主线程捕获、内存、缓存命中与降级次数。暂定实施门槛：中文换言与跨语言两个目标切片的 Recall@k 至少提升 10 个百分点，整体 Precision@k 不下降，精确实体、完整列举、权威/隐私、删除和既有计数测试零回归，且满足上面的延迟预算。门槛可以讨论，但达到门槛前不宣称已有语义收益。
