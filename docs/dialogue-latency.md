# 对话等待与推理模型兼容

2026-09-08 的游戏日志记录了一轮 `gpt-5.6-luna` 对话总耗时 65,877ms，
其中语义路由在 12,000ms 超时并回退到 39,312 字符的完整提示词，动作补救也失败。
同批平台截图有 29.44 秒、68 秒、78 秒的单次请求。平台记录不能直接等同于
游戏中每个阶段的等待：客户端取消后，转发服务仍可能继续处理上游请求。

此前一轮交互依次等待路由、正文、完整元数据；元数据失败时还会等待动作补救。
元数据和补救的内部超时各为 12 秒。`12 + 29.44 + 12 + 12 ≈ 65.44` 秒与截图吻合，
但旧日志没有每段计时，不能据此认定某个平台记录必然对应其中某段。

## 本次修复

- DeepSeek v4 的 `Low` / `Minimal` 发送 `reasoning_effort: low`。此前误发 `high`。
  旧 R1 / reasoner 的能力映射不跟随 v4 修改。
- 空正文、`finish_reason: length` 或仅推理的终态响应不再跨候选、跨引擎反复重试。
  错误仅记录停止原因与 token 用量，不把 `reasoning_content` 当正文或打印整段内容。
- HTTP 400/422 直接切换兼容请求形式；瞬态错误继续保留重试。
  仅瞬态失败不删除思考控制，DeepSeek 的明确 Off 也不会因裸请求回退而被重新开启。
  鉴权失败立即结束；限流和连接故障只重试原请求形式，不重复切换消息格式或流式通道。
- 如果转发服务无视 `stream` 而返回完整 JSON，第一次收到就消费结果与真实用量。
- 只有整句为首轮问候时直接构建保守简要上下文，所有原有硬依赖仍会应用。
  实质问题和后续话轮继续语义路由；失败的完整上下文仅在当前会话复用，避免反复等待超时。
  NPC、会话、日期、连接、模型或端点变化会让缓存失效。
- 动作补救只由本轮实际话语、最近的约定或活跃求助触发。
  通用动作规则、字段名和“没有授权送礼”等背景文字不再让普通寒暄额外请求模型。
- 元数据支持 `{"complete":true,...}` 的稀疏完整回复，仅输出有变化的字段。
  省略项由程序填默认值；完整性标记、字段类型与已有证据约束仍会检查。
  老版完整结构继续兼容，没有完整性标记的残缺结构继续失败回退。
- 调试日志分别输出路由、正文、元数据和动作补救的结果及毫秒数。

正文、情绪、关系、记忆和世界动作仍在同一次生成中完成校验，展示成功后在主线程提交。
没有把副作用移到任意后台任务，以免玩家离开、取消或切换对话后提交过期结果。

## 验证与实际速度

回归测试使用可计数的本地客户端及模拟 HTTP，覆盖请求次数、模型参数、完整/稀疏元数据、
直接及多轮承诺、取消与展示后提交。普通首轮问候只需正文和元数据两次逻辑请求；
元数据失败也不会仅因通用规则而再启动动作补救。供应商内部仍可能因真正瞬态故障重试。
本轮完整测试为 1,899 项通过、0 项失败、1 项原有跳过。

没有使用用户密钥做付费在线压测，因此本次不报告一个未经实测的提速百分比或秒数。
`Low` 降低推理强度，不会消除推理、网络传输及供应商排队。
新日志可分清时间花在何处；单次正文请求若仍长达几十秒，客户端改动无法保证其秒回。
现有模型选择、思考档位和超时配置保持用户设定。

官方参数依据：

- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)：v4 支持 low/high/max，默认开启思考。
- [OpenAI Reasoning](https://developers.openai.com/api/docs/guides/reasoning)：推理与可见回复共享输出预算，推理强度影响耗时。
