# 对话等待与推理模型兼容

## 2026-09-09：单次生成与真实请求验证

在用户授权后，使用游戏配置中的 `OpenAiCompatible / gpt-5.6-luna` 发送了
29 次顺序测试请求，全部使用合成对话。18 次返回非空正文，11 次出现空正文、
HTTP 503 或超时。请求参数、耗时与供应商返回的用量保存在
[脱敏测量记录](benchmarks/dialogue-latency-20260909.json)；记录不含端点、密钥或玩家存档。
有用量的响应合计报告 168,838 个输入 token、3,802 个输出 token（其中报告了
1,501 个推理 token）。失败请求缺失用量，因此这些数字不能当作完整账单。

本轮实施：

- 主动对话和送礼反应同时生成正文与末尾 `!LIVINGNPCS_META {"complete":true,...}`。
  严格检查完整 JSON、字段类型、重复字段、末尾位置与当前话语证据；通过时省去独立分类请求。
  缺失、损坏、明确递送礼物却漏写动作、偏好分值低于持久存储门槛时，仍调用原分类器。
  元数据协议与分类器共用，取消、正文清理、原生窗口及展示成功后提交的顺序保持一致。
- 明确记忆重要度采用 0–100，保存门槛为 40。最初实测中的偏好错误地给出 3/2 分，
  会被存储层丢弃；修订协议后的独立真实样本给出 70/65，经过实际偏好存储代码验证两条均保存。
  该样本缩短了场景上下文，只用于协议质量检查，不用它声称游戏提速。
- 新增可选 `UseStreamingDialogueTransport`。OpenAI 兼容端点在后台流式收齐主回复，
  然后交给原生对话框；不存在预览后重放。正文与用量、终止标记、断连、取消和整个请求的
  截止时间都受检查。快速分类请求仍走原通道。不支持流式的端点保留非流式兼容回退。
  开关默认关闭，便于其他兼容接口保持原配置；本机经过流式实测后启用。
- 502/503/504 不再通过切换消息格式或非流式通道反复请求不可用的网关。
  暂时故障只保留原格式的有限重试，400/422 的兼容回退仍保留。
- 世界阶段说明在有持久状态时只输出一份，样例减少约 1,031 字符。
  无持久状态时保留原有提示，避免末尾指导提前返回导致事实丢失。

本机部署配置关闭 `EnableSemanticContextRouting`，每轮直接使用完整上下文，省去前置模型请求；
保留 `ChatThinkingLevel=Low`、`RoutingThinkingLevel=Low` 以及原模型、端点和超时。
两个旧精简开关仍关闭：它们会删减部分世界地点、社区印象或复杂关系指导，不能把这种删减当成无损提速。
关闭路由也会使原先纯问候的简略上下文变为完整上下文，不能保证这类回合更快。

实测结果需要同时看成功、变慢和失败的样本：

| 对照 | 观察结果 |
| --- | --- |
| 同一短对话，Low / none，ABBA 顺序 | Low 6.95 / 10.54 秒；none 73.14 / 10.94 秒。其中一次 none 仍报告推理 token。 |
| 相同完整拍照场景 | 旧路由 12.22 秒超时 + 正文 37.91 秒 + 分类 12.01 秒超时，合计约 62.1 秒；合并流式请求 18.68 秒。 |
| 相同求助场景 | 旧正文与实际回复的分类合计 13.05 秒；合并流式请求 35.39 秒。两次生成的文本与输出长度不同。 |
| 首组完整上下文单请求 | 六条成功为 6.16–30.76 秒，两条在约 31/34 秒返回 HTTP 200 空正文。 |
| 后续完整上下文 | Low 与 none 都发生约 85 秒超时；一条有效求助耗时 73.74 秒。 |

因此可以确认减少了正常交互的串行请求数，但**没有证据支持稳定的全局提速倍数或秒回承诺**。
这条转发服务的排队、生成速度或可用性波动仍会决定等待上限，客户端无法从响应推断具体是哪一个。
新日志的路由、主请求、元数据、动作恢复计时可继续区分这些阶段。

8 类合成场景经过真实模型输出与本地处理链检查：普通问答、偏好、即时赠礼、延期邮件、
求助、接受邀约、明确边界、拒绝邀约。检查覆盖解析、物品 ID、偏好存储门槛、求助一致性及出行过滤，
不等于在运行中的游戏里实际发放物品或执行出行。完整上下文的偏好修订请求受到服务超时影响，
偏好修订的在线成功证据来自上述独立协议样本；低分原始输出另有分类器回退回归测试。

最终完整回归：2,044 项通过、0 失败、1 项原有跳过；离线诊断 8/8 通过。
新增测试覆盖单请求/回退次数、低分偏好真实存储、赠礼方向、SSE 用量、真实结束标记、
非流式兼容回退、503、空正文、流中断、取消、完整读取超时及展示前不提交副作用。

复测工具：[benchmark_dialogue_latency.py](../tools/benchmark_dialogue_latency.py)。
它只读取指定配置里的模型和凭据，默认执行四条合成短对话；`--fixtures` 可传入合成请求数组。
每个元素包含 `name/system/user/effort/stream/max_tokens`，可选 `json_mode`、`timeout_seconds`
及 `metadata_followup`（用实际主回复填入导出的分类器数据块）。工具不自动重试，遇到鉴权、
限流或网关不可用错误停止，记录不含隐藏推理。运行依赖 Python 和 `requests`。

## 2026-09-08 版本记录

2026-09-08 的游戏日志记录了一轮 `gpt-5.6-luna` 对话总耗时 65,877ms，
其中语义路由在 12,000ms 超时并回退到 39,312 字符的完整提示词，动作补救也失败。
同批平台截图有 29.44 秒、68 秒、78 秒的单次请求。平台记录不能直接等同于
游戏中每个阶段的等待：客户端取消后，转发服务仍可能继续处理上游请求。

此前一轮交互依次等待路由、正文、完整元数据；元数据失败时还会等待动作补救。
元数据和补救的内部超时各为 12 秒。`12 + 29.44 + 12 + 12 ≈ 65.44` 秒与截图吻合，
但旧日志没有每段计时，不能据此认定某个平台记录必然对应其中某段。

## 本次修复

- DeepSeek v4 的 `Low` / `Minimal` 发送 `reasoning_effort: low`。此前误发 `high`。
  旧 R1 / reasoner 的能力映射不跟随 v4 修改。
- 空正文、`finish_reason: length` 或仅推理的终态响应不再跨候选、跨引擎反复重试。
  错误仅记录停止原因与 token 用量，不把 `reasoning_content` 当正文或打印整段内容。
- HTTP 400/422 直接切换兼容请求形式；瞬态错误继续保留重试。
  仅瞬态失败不删除思考控制，DeepSeek 的明确 Off 也不会因裸请求回退而被重新开启。
  鉴权失败立即结束；限流和连接故障只重试原请求形式，不重复切换消息格式或流式通道。
- 如果转发服务无视 `stream` 而返回完整 JSON，第一次收到就消费结果与真实用量。
- 只有整句为首轮问候时直接构建保守简要上下文，所有原有硬依赖仍会应用。
  实质问题和后续话轮继续语义路由；失败的完整上下文仅在当前会话复用，避免反复等待超时。
  NPC、会话、日期、连接、模型或端点变化会让缓存失效。
- 动作补救只由本轮实际话语、最近的约定或活跃求助触发。
  通用动作规则、字段名和“没有授权送礼”等背景文字不再让普通寒暄额外请求模型。
- 元数据支持 `{"complete":true,...}` 的稀疏完整回复，仅输出有变化的字段。
  省略项由程序填默认值；完整性标记、字段类型与已有证据约束仍会检查。
  老版完整结构继续兼容，没有完整性标记的残缺结构继续失败回退。
- 调试日志分别输出路由、正文、元数据和动作补救的结果及毫秒数。

正文、情绪、关系、记忆和世界动作仍在同一次生成中完成校验，展示成功后在主线程提交。
没有把副作用移到任意后台任务，以免玩家离开、取消或切换对话后提交过期结果。

## 验证与实际速度

回归测试使用可计数的本地客户端及模拟 HTTP，覆盖请求次数、模型参数、完整/稀疏元数据、
直接及多轮承诺、取消与展示后提交。普通首轮问候只需正文和元数据两次逻辑请求；
元数据失败也不会仅因通用规则而再启动动作补救。供应商内部仍可能因真正瞬态故障重试。
本轮完整测试为 1,899 项通过、0 项失败、1 项原有跳过。

没有使用用户密钥做付费在线压测，因此本次不报告一个未经实测的提速百分比或秒数。
`Low` 降低推理强度，不会消除推理、网络传输及供应商排队。
新日志可分清时间花在何处；单次正文请求若仍长达几十秒，客户端改动无法保证其秒回。
现有模型选择、思考档位和超时配置保持用户设定。

官方参数依据：

- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)：v4 支持 low/high/max，默认开启思考。
- [OpenAI Reasoning](https://developers.openai.com/api/docs/guides/reasoning)：推理与可见回复共享输出预算，推理强度影响耗时。
